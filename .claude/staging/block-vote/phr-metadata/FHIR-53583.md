# FHIR-53583: Need new location for Metadata, now that DocumentManifest isn't available

**JIRA:** https://jira.hl7.org/browse/FHIR-53583
**Status:** Submitted | **Resolution:** None
**Proposed Resolution:** Persuasive with Modification

## Ballot Comment
DocumentManifest had the metadata capabilities needed for the PHR file format but was removed in FHIR R5. Where should this metadata go now? Also, terminology issues: Lifelog vs Longitudinal, Problem List vs Concern List.

## Proposed Action
1. Replace DocumentManifest reference in `datastorage.md` line 26 with an alternative:
   - **Option A:** Use IPS Composition as the metadata container (already in scope)
   - **Option B:** Use List resource to enumerate contents
   - **Option C:** Use a custom manifest.json within the .sphr zip structure (already partially described in annotations.md)
2. Reconcile `datastorage.md` (still references DocumentManifest) with `recordkeeping.md` (uses IPS)
3. Address terminology: standardize on "Longitudinal Record" (not Lifelog) and "Problem List" (FHIR standard term)

## Affected Files
- `input/pagecontent/datastorage.md` — Line 26: replace DocumentManifest reference
- `input/pagecontent/recordkeeping.md` — Ensure consistency with datastorage.md
