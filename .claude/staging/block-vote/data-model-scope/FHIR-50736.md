# FHIR-50736: Clarify that data model is for FHIR IG, not for PHR

**JIRA:** https://jira.hl7.org/browse/FHIR-50736
**Status:** Triaged | **Resolution:** None
**Ballot:** may-2025 | **Section:** 4
**Proposed Resolution:** Persuasive
**Block Vote:** Data Model Scope (Block D) — with FHIR-50737

## Ballot Comment
Change "At the core of the Standard Patient Health Record is the assumption that it will contain records in FHIR format..." to "The intention of the PHR FHIR Implementation Guide is to provide the standard mechanism for the communication of any of the records contained in a particular PHR." Important that the spec not be confused with a spec for how to build a PHR.

## Proposed Action
1. Update `datamodel.md` opening paragraph (lines 1-5) with the commenter's suggested language
2. Ensure the page frames FHIR as the communication/exchange format, not a storage mandate
3. Remove any language implying PHR systems MUST store data internally as FHIR

## Affected Files
