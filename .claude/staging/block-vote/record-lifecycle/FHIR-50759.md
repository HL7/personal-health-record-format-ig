# FHIR-50759: Several statements regarding record lifecycle section appear incorrect

**JIRA:** https://jira.hl7.org/browse/FHIR-50759
**Status:** Triaged | **Resolution:** None
**Ballot:** may-2025 | **Section:** 23.0.1
**Proposed Resolution:** Persuasive with Modification
**Block Vote:** Record Lifecycle (Block B) — with FHIR-50739, FHIR-50756

## Ballot Comment
References to a vendor-owned "Patient Data Receipt IG" as a "standard" — it is not an HL7 standard. Inappropriate to refer to one vendor's guide as if it were a standard. Perhaps the goal is for that guide to become part of HL7 but would need MITRE approval.

## Proposed Action
1. Remove or reframe references to the "Patient Data Receipt" as a vendor-specific implementation, not a standard
2. If keeping the page: replace vendor-specific references with HL7 standard alternatives (Provenance, AuditEvent)
3. If removing the page (per FHIR-50739): this is automatically resolved

## Affected Files
- `input/pagecontent/recordlifecycle.md` — Remove vendor-specific references

## Implementation Notes
- The Patient Data Receipt was a MITRE-developed concept for tracking data provenance
- `input/fsh/models/PatientDataReceipt.fsh` exists as a logical model — also needs review (see FHIR-50765)
- The commenter's concern is valid: vendor-specific artifacts should not be presented as standards in a UV IG
- This is also related to FHIR-50765 (Experimental Logical Models) since PatientDataReceipt is one of the models
